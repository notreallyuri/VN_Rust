# The macros behind commands

`novn-macros` holds the two macros that sit on the seam between a story and the Rust behind
it. `#[command]` turns a function into something a story can `call`, and
`#[derive(StoryWord)]` turns an enum into the fixed set of words such a call accepts.

You never name this crate in a `Cargo.toml`. `novn` re-exports both and has them in its
prelude, so `use novn::prelude::*` is the whole setup.

## `#[command]`

```rust
use novn::prelude::*;

#[command]
fn give_item(ctx: &mut GameContext, item: String, count: Option<u32>) -> Option<ScreenState> {
    ctx.state.get_mut::<Inventory>().add(&item, count.unwrap_or(1));
    None
}

VnApp::new("My Novel").command(give_item)
```

```story
call give_item verlaine_letter
call give_item candle 3
```

The first parameter is the context. Everything after it is an argument the story writes on
the line, and the types decide how the line is parsed. An `Option` makes the argument
optional, which is why the second call above may leave the count off.

### What it writes

The function becomes a marker type of the same name, carrying what the engine needs:

| Piece | From |
| --- | --- |
| `NAME` | The function's own name, or the one in `#[command("other_name")]` |
| `Args` | The parameters after the context, as the tuple `FromArgs` parses out of the line. `()` for none, or `Vec<String>` alone for "the rest of the line" |
| `run` | Unpacks that tuple and calls the body |
| `call` | The body as an ordinary function, so Rust can run the command directly: `give_item::call(ctx, "candle".into(), Some(3))` |

That marker is what `VnApp::command` takes. It is the reason the name is written once and
checked by the compiler, rather than repeated as a string that drifts.

The story-facing signature, how many arguments and of what kind, is derived from the
parameter types, written into `schema.json`, and checked against every `call` in the story.
[Engine commands](/docs/commands) has the types a parameter may have.

### What it refuses

Each of these is a compile error at the offending span, rather than a surprise at startup.

- A name a story could not write. `call` takes lowercase letters, digits and `_`, not
  starting with a digit.
- `async` functions, generic functions, and methods taking `self`.
- A borrowed argument. The arguments are parsed out of the story line, so they are owned:
  `String`, not `&str`.
- A function with no return type. A command returns `Option<ScreenState>`, where `None` stays
  in the story and `Some(state)` switches screens.

A closure has no name to take, so it stays with `VnApp::command_as("name", |ctx, ()| ...)`.

## `#[derive(StoryWord)]`

When an argument is one word out of a fixed set, make it an enum.

```rust
#[derive(StoryWord, Clone, Copy, PartialEq, Eq)]
enum Note {
    DebtPaid,
    #[word("folio_41")]
    Folio41,
    HotWater,
}
```

| Piece | What it is |
| --- | --- |
| `as_str`, `Display` | The word: the variant in snake_case, or the `#[word("...")]` it was given |
| `from_word(&str)` | The variant, or `None` |
| `ALL` | Every variant, in the order they are written |
| `Default` | The first variant |
| `FromArg`, `Arg` | What lets `#[command] fn note(ctx: &mut GameContext, key: Note)` take it |
| `Serialize`, `Deserialize` | Through the word, so a save file holds the same string the story writes |

### Why it is worth the derive

The set reaches the tooling. An argument of this type is a `ParamKind::Choice`, which goes
into `schema.json`, so `novn check` rejects a word outside the set and suggests the nearest
one, and the LSP offers the words while you are still typing the `call` line. A typo becomes
an error in the editor instead of a wrong branch three hours into playtesting.

Deserializing a word the enum no longer has is an error that names the ones it does have,
rather than quietly falling back to the first variant. An old save tells you what changed.

### Naming

Variants convert on letter and digit boundaries: `EndingKeeper` becomes `ending_keeper`,
`Box14` becomes `box_14`, `Folio41` becomes `folio_41`. Where that is not the word you want,
`#[word("...")]` says so.

Two variants may not claim the same word, a variant may not carry data, and a word a story
could not write is a compile error, on the same rule as a command's name.

## Tests

Both macros are exercised from `novn`, where the engine half of them lives, in
`crates/novn/tests/commands.rs`: names and renaming, the signature flat parameters produce,
argument parsing, registration through the builder, and for story words the snake_case
conversion, `#[word]`, the declared choices, the error for a word outside the set, and the
serde round trip.
