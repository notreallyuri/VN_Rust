# Dev tools

novn has no visual editor, on purpose. Logic lives in Rust, where Rust's own tools debug it,
and a WYSIWYG editor is something Godot and Unity already do better. What it has instead is
what Ren'Py settled on too: hot reload, and a handful of tools inside the running game that
cut out the slow parts of iterating on a story.

All of them are on in debug builds and off in release builds, so none of them can ship to a
player by accident.

```rust
VnApp::new("My Novel")
    .dev_tools(false)
```

`.dev_tools(false)` turns them off while you develop, and `.dev_tools(true)` turns them on in
a release build, for a tester's copy.

| Key | Tool |
| --- | --- |
| F2 | The story error panel, when a hot reload failed. See [hot reload](/docs/engine/story#hot-reload) |
| F3 | The inspector: what is drawn where, the focus order, and frame timing |
| F4 | Jump to a scene |
| F6 | The position picker, while playing |
| F7 | The director, while playing |
| F12 | A screenshot, from any screen |
| Shift+F12 | Start or stop a GIF recording |

They draw in their own plain style rather than your game's theme, so a tool stays readable
however the game looks, and they only use characters every font has.

## The inspector

F3 turns it on and off, and the game keeps running underneath, so you can click, hover and
play while it watches. It is the fastest way to answer "why is that button there".

**Every widget is outlined.** Buttons and panels, which covers menus, the dialogue box, the
name plate, save slots, choices, toasts and tooltips.

**Point at one to read it.** The widget under the pointer lights up, and a card beside it
gives its rect in the game's own coordinates and the style it was drawn with.

| Kind | What the card shows |
| --- | --- |
| Button | Its label and rect, the size its style asked for, font role, size and colour, fill, padding, alignment and overflow, border, and whether it has an image, icon or transform |
| Panel | Its rect, fill, gradient, border, inner border and shadow |
| Character | Its id and image, where it stands as a fraction of the width, and its texture's size against the scale it is drawn at |

That last line is worth a glance now and then: a 1024 by 1536 portrait drawn at 0.38x is
art about two and a half times bigger than it is ever shown, and it costs memory at that
size the whole time it is loaded.

The rect and the configured size side by side is the useful part: a button whose rect is
narrower than its style is being squeezed by a layout, and that is the usual answer to text
that ellipsizes when it should not.

**The focus order is numbered.** Every list that keyboard and gamepad navigation moves
through gets its items numbered in the order Tab visits them. The focused one is outlined,
and disabled ones are greyed. The numbers show even when a mouse user has nothing focused,
which is when a wrong order is easiest to miss.

**Frame timing sits in a corner.** Frames per second, the average and the worst frame of
the last two seconds, and a graph with a line at 60 fps and spikes over it in red. The
loading hitch when a scene brings in new art shows up here. The graph moves to the other
corner when the pointer comes near it, so it never covers what you are inspecting.

It costs nothing while it is off: a widget checks one flag before recording anything, and
nothing is recorded in a release build at all.

## Jump to a scene

Replaying chapter one to check a line in chapter four is the slowest loop in writing a visual
novel. F4 opens every scene in the story, in the order the files load, each with the file and
line it starts on, next to every variable the game registered and its value right now.

Pick a scene, change the variables it depends on, and press Enter.

| Input | Does |
| --- | --- |
| Up and Down | Move through the list |
| Tab, or Right from the scenes | Switch between scenes and variables |
| Left and Right on a variable | Flip a `bool`, step an `int`, cycle an enum's members |
| Enter | Jump |
| Click a scene | Select it. Click it again to jump |
| Click a variable | Change it: the left half steps back, the right half forward |
| Esc, or a click outside | Close |

It works on the start screen, the main menu, or halfway through a line. The one place it
stays shut is a text input screen, the same as F1.

**The values start from where you are.** Open it mid-game and every variable holds its
current value, so a jump carries your state with it unless you change something. A value you
changed is marked until you jump. Strings are shown but not editable, since a name the player
typed has no sensible "next".

**A jump is a new game at that scene.** The story starts there with the values in the panel,
and everything else starts over the way New Game does: your Rust game state, the log, play
modes and rollback history. Rolling back past a jump would land in a story that never
happened, so there is nothing to roll back to.

It opens on the scene being played, so pressing Enter straight away restarts the current
scene with the current values, which is a quick way to see a scene again after editing it.

## The position picker

F6 while playing, then drag a character across the stage. The sprite follows the pointer,
the five `at` slots are drawn as guides, and the one you are nearest lights up.

Letting go copies the line for your story, and prints it to the console:

```story
show registrar neutral at far_left
```

The language places characters at five named slots rather than at coordinates, which keeps
a story readable and lets the game move all of them at once. So the picker gives you the
nearest slot for the story, and the exact spot in Rust for the other case, where the slot
itself is in the wrong place. Enter copies that:

```rust
VnApp::new("My Novel")
    .playing(|p| p.position(Position::FarLeft, 0.208))
```

Nothing you drag changes the story. The character is only drawn somewhere else while the
picker is open, and Esc, F6 again, or anything that leaves the screen puts them back where
the story has them. A character drawn by a [visual backend](/docs/engine/visuals) rather
than an image can't be picked up yet.

## The director

F7 while playing opens a panel down the right side. Pick what to add, then move through
what your assets folder holds, and each one plays out on the stage as you land on it: a
background swaps in, a character steps on, a track crossfades, a sound or voice line plays.
Nothing about the story changes while you browse. Hold H to hide the panel and see the whole
stage.

| Pick | Lists | Previews by |
| --- | --- | --- |
| `show` | Every image under `characters/<id>/` | Standing the character on stage, or changing the image of one already there |
| `background` | Every image in `backgrounds/` | Swapping it in |
| `music` | Every track in `music/` | Crossfading to it |
| `sound` | Everything in `sounds/` | Playing it once |
| `voice` | Everything in `voice/` | Playing it once |

Enter writes the line into your `.story` file, directly above the line on screen and at its
indentation, so it happens right where you were looking. The panel says which file and line
before you commit to anything. Hot reload then restarts the scene with the line in it, and
the director closes, since the line it was pointing at has just moved.

```story
  show registrar neutral at right with dissolve
  background field_post
  registrar "You're the new one. Sit."
```

**It will not break your story.** The file is compiled with the new line before anything is
written, and if the line would add an error, say a `background` among a choice's options,
nothing is written and the panel says why. A story that already has an error elsewhere can
still be directed, as long as the new line does not add another.

**It lists what the engine can load, and nothing else.** Looking a file up is
case-sensitive, and the engine asks for `night.png`, so a `Night.PNG` would load on your
machine and show a placeholder on another. It is left out rather than offered. The same goes
for names a story could not write, like `old-attic`.

It needs the story in a folder on disk. A build that embeds its story has no file to write
to, and says so.

## Screenshots and recordings

For bug reports and devlogs. Both land in the `screenshots` folder beside your saves, next to
the ones a player takes with `S`, and the console prints the path.

**F12** takes a screenshot from any screen: the main menu, the settings, the middle of a
choice, with the inspector open if it is. The player's `S` only works while playing.

**Shift+F12** starts a GIF and Shift+F12 again stops it. A red REC badge counts the time in
the corner, and it never appears in the recording: it is drawn after the frame is captured.
Recordings stop by themselves at 30 seconds.

It records at 15 frames a second, scaled to 640 pixels wide, and every frame is held on
screen for as long as it really was, so a hitch while a scene loads plays back as a hitch
rather than being smoothed over. Encoding happens on a thread of its own, and the game never
waits for it. If it ever falls behind, frames are dropped rather than the game slowed, and
the console says how many.

**Only what changed is stored.** A visual novel is mostly still: the background holds while
text types into one box. Each frame keeps only the rectangle that differs from the one before,
and a frame with no change at all just lengthens the previous one. Six seconds of the example
game went from 12.4 MB to 0.7 MB this way, so a full thirty-second recording is a few
megabytes and fits where you would post it.

Close the game mid-recording and the file is still finished properly before it exits.
