# Dev tools

novn has no visual editor, on purpose. Logic lives in Rust, where Rust's own tools debug it,
and a WYSIWYG editor is something Godot and Unity already do better. What it has instead is
what Ren'Py settled on too: hot reload, and a handful of tools inside the running game that
cut out the slow parts of iterating on a story.

All of them are on in debug builds and off in release builds, so none of them can ship to a
player by accident.

```rust
VnApp::new("My Novel")
    .dev_tools(false)
```

`.dev_tools(false)` turns them off while you develop, and `.dev_tools(true)` turns them on in
a release build, for a tester's copy.

| Key | Tool |
| --- | --- |
| F2 | The story error panel, when a hot reload failed. See [hot reload](/docs/engine/story#hot-reload) |
| F3 | The inspector: what is drawn where, the focus order, and frame timing |
| F4 | Jump to a scene |

They draw in their own plain style rather than your game's theme, so a tool stays readable
however the game looks, and they only use characters every font has.

## The inspector

F3 turns it on and off, and the game keeps running underneath, so you can click, hover and
play while it watches. It is the fastest way to answer "why is that button there".

**Every widget is outlined.** Buttons and panels, which covers menus, the dialogue box, the
name plate, save slots, choices, toasts and tooltips.

**Point at one to read it.** The widget under the pointer lights up, and a card beside it
gives its rect in the game's own coordinates and the style it was drawn with.

| Kind | What the card shows |
| --- | --- |
| Button | Its label and rect, the size its style asked for, font role, size and colour, fill, padding, alignment and overflow, border, and whether it has an image, icon or transform |
| Panel | Its rect, fill, gradient, border, inner border and shadow |

The rect and the configured size side by side is the useful part: a button whose rect is
narrower than its style is being squeezed by a layout, and that is the usual answer to text
that ellipsizes when it should not.

**The focus order is numbered.** Every list that keyboard and gamepad navigation moves
through gets its items numbered in the order Tab visits them. The focused one is outlined,
and disabled ones are greyed. The numbers show even when a mouse user has nothing focused,
which is when a wrong order is easiest to miss.

**Frame timing sits in a corner.** Frames per second, the average and the worst frame of
the last two seconds, and a graph with a line at 60 fps and spikes over it in red. The
loading hitch when a scene brings in new art shows up here. The graph moves to the other
corner when the pointer comes near it, so it never covers what you are inspecting.

It costs nothing while it is off: a widget checks one flag before recording anything, and
nothing is recorded in a release build at all.

## Jump to a scene

Replaying chapter one to check a line in chapter four is the slowest loop in writing a visual
novel. F4 opens every scene in the story, in the order the files load, each with the file and
line it starts on, next to every variable the game registered and its value right now.

Pick a scene, change the variables it depends on, and press Enter.

| Input | Does |
| --- | --- |
| Up and Down | Move through the list |
| Tab, or Right from the scenes | Switch between scenes and variables |
| Left and Right on a variable | Flip a `bool`, step an `int`, cycle an enum's members |
| Enter | Jump |
| Click a scene | Select it. Click it again to jump |
| Click a variable | Change it: the left half steps back, the right half forward |
| Esc, or a click outside | Close |

It works on the start screen, the main menu, or halfway through a line. The one place it
stays shut is a text input screen, the same as F1.

**The values start from where you are.** Open it mid-game and every variable holds its
current value, so a jump carries your state with it unless you change something. A value you
changed is marked until you jump. Strings are shown but not editable, since a name the player
typed has no sensible "next".

**A jump is a new game at that scene.** The story starts there with the values in the panel,
and everything else starts over the way New Game does: your Rust game state, the log, play
modes and rollback history. Rolling back past a jump would land in a story that never
happened, so there is nothing to roll back to.

It opens on the scene being played, so pressing Enter straight away restarts the current
scene with the current values, which is a quick way to see a scene again after editing it.
